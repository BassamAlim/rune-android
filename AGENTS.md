# AGENTS.md

## What Rune is

A deterministic password generator for Android: one master password becomes a different
password for every site. Nothing is stored except the wrapped master key and a
list of site names and settings, plus, until switched to Rune's, a site's old password sealed under
the master key (SPEC §3.1; `core/crypto/Seal.kt`). The `INTERNET` permission exists for two things only: fetching
each site's `/favicon.ico` and homepage from that site, for its logo and display name (`SiteIcons`),
and syncing the site list with the desktop over the local network, sealed under a key both derive
from the master key (`core/sync/Sync.kt`, SPEC §3.3). The desktop never keeps the master key, so
it asks this phone for a password (or to seal one) on the same connection; the phone shows what
is asked and a code to compare, and answers only after its own unlock, sealed under a one-time
key the two agree (`core/sync/Approvals.kt`, SPEC §3.4). Nothing else goes on the network: no
password except an approved answer to the desktop, and never the master key.

The algorithm, the site-list file format and the security model are specified in
`rune-desktop/SPEC.md` (a sibling repo, which also holds the Rust desktop app). That document is
the contract; this app and the desktop app must produce identical passwords.

## Stack

- Kotlin, Jetpack Compose, Material 3 — AGP 9 with built-in Kotlin support (do **not** apply
  `org.jetbrains.kotlin.android`; AGP 9 rejects it)
- Hilt for DI, KSP for annotation processing (never KAPT)
- DataStore Preferences for the wrapped keys; one JSON file for the site list
- Navigation Compose with **type-safe routes** (`@Serializable` destinations in `core/nav/Screen.kt`)
- AndroidX Biometric with a Keystore-bound `CryptoObject`; Bouncy Castle for Argon2id and X25519 only
- Version catalog: `gradle/libs.versions.toml`. Add dependencies there, never inline.

## Architecture

MVVM over a single data layer. Dependencies point one way: UI → ViewModel → Domain → Repository
/ Vault. Nothing below the ViewModel knows about Compose.

```
core/
  crypto/Rune.kt           the rune/v1 algorithm: pure functions, no Android types
  vault/                   Vault (the Keystore-wrapped master key) and Unlocker (the unlock ceremony)
  data/repositories/       SitesRepository: the only way into the site list; SiteIcons: app icons
                           and favicons for avatars (via LocalSiteIcons, unset in screenshot tests)
  models/                  Site, SiteList and the list rules (add, merge, remove; SPEC §3.2)
  sync/                    Sync: finds the desktop on the local network and exchanges lists;
                           Approvals: answers what the desktop asks for, behind ApprovalSheet
  autofill/                the AutofillService, form parsing, site matching, AutofillActivity
  di/                      Hilt modules for things Hilt can't construct itself
  nav/                     Screen (routes), Navigator, Navigation (the graph)
  ui/theme/                design tokens: Color, Type, Shape, Dimens, Theme
  ui/components/           shared composables, including UnlockPrompts
  utils/                   small helpers
features/<feature>/
  <Feature>Screen.kt       composables only; stateless inner composable + a hoisted wrapper
  <Feature>ViewModel.kt    @HiltViewModel; exposes one StateFlow<UiState>
  <Feature>UiState.kt      immutable state
  <Feature>Domain.kt       the feature's logic, injected into the ViewModel
```

Rules that matter:

- **`Rune.kt` is frozen by `vectors.json`.** Any change that alters an output changes every
  password the user has. The vectors test must pass unchanged; a real algorithm change means
  `rune/v2` and new vectors generated by the desktop repo.
- **The master key is used once and zeroed.** Whoever receives it from `Unlocker` or `Session`
  passes it to `Site.passwords(masterKey)`, which zeroes it. Only `Session` keeps it, and don't log.
- **The fingerprint that opens the app is the one unlock.** With fingerprint unlock on, the app
  opens locked; passing it puts the master key in `Session`, and `SiteViewModel` takes a copy
  from there instead of asking again. Leaving the app for `Globals.LOCK_GRACE_MILLIS` closes the
  session and locks the app. Without fingerprint unlock there is no session: each password asks
  for the master password. `SiteViewModel.onHidden` forgets the password when the screen stops.
- **The autofill service never holds a password.** It returns locked datasets;
  `AutofillActivity` authenticates and returns the filled one.
- **Only browsers in `SiteMatcher.BROWSERS` are believed about a web domain.** Other apps match
  only through a site's `apps` list, which only a user's own pick can add to.
- **Every change to the site list goes through `SiteList.with` / `without`,** which stamp it
  (SPEC §3.2). A change that skips them loses to older copies when devices sync.
- **A site list that can't be read stops the app** (`SitesState.Unreadable`) rather than being
  replaced with an empty one: counters can't be recomputed.
- **Navigation goes through `Navigator`** (injected into ViewModels). Nothing outside `core/nav`
  touches a `NavController`.
- The inner stateless screen composables are `internal` rather than `private` so
  `ScreenshotTest` can render them from hand-made state.

## Design system

Tokens live in `core/ui/theme/` and are the only source of colour, type, spacing and radius.
Don't hardcode hex values or `.dp` literals that aren't on the scale in `Dimens.kt`.

- **Dark only**, shared with the desktop app: warm near-black surfaces and one amber accent
  `#FFB020`.
- **One filled accent button per screen.** Destructive actions are outlined in `Danger`, never
  filled.
- Type is Space Grotesk (interface) and JetBrains Mono (passwords, keys, the fingerprint), bundled as
  variable fonts in `res/font/`.
- The mark is ᚱ, the R rune: `ic_rune_mark`, used at every size, and the launcher icons. All are
  generated by `rune-desktop/scripts/mark/assets.py`; change the shape there, not by hand.
- **Icons are stroke glyphs** in `res/drawable/ic_*.xml`, used with `painterResource`. There is
  no `material-icons` dependency — don't add one.
- Every field has a visible label above it; errors sit under the field they are about and
  always carry an icon or text, never colour alone.

## What can't be tested here

Keystore, BiometricPrompt, the autofill service and a real sync (a desktop on the same Wi-Fi)
need a real device or emulator. The unit
tests cover the algorithm, the site-list rules, form parsing and site matching; the screenshot
test covers layout. Anything touching `Vault`, `Unlock.kt` or `core/autofill/RuneAutofillService`
must be tried on a phone.
